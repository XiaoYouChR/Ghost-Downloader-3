# 非整数缩放的 Windows 滚轮绕开平滑动画，只在吞帧时启用

ADR 0019 把 `QUnifiedTimer` 的间隔按主屏刷新率压到 6ms（165Hz），`SmoothScrollArea` 的 500ms `QPropertyAnimation` 于是每帧只推进 1~2 逻辑像素。同一份决策里的「整物理像素滚动」又要求位移落在整物理像素上：125% 缩放（DPR=1.25）时是 4 逻辑像素。两者叠加，多数动画帧量化后位移为 0（120px / 85 帧里约 55 帧），列表只能以 4px 阶梯跳动；Mica 半透明背景每帧合成会放大观感。100% 缩放或 60Hz 屏都不触发。

滚轮事件在 viewport 上由 QFW 的 `SmoothScrollDelegate` 过滤后交给 `SmoothScrollBar` 做动画。我们在它之后装一个过滤器（Qt 后装先收事件），拦下 Wheel 并直接设置**原生** `QScrollBar` 的值为整步长倍数：原生滚动条没有动画，`QScrollArea` 立即平移已绘制像素；量化钩子收到已对齐的值后同值收敛，不会递归。触控板 `pixelDelta` 的零碎增量留在余数里累积。滚到尽头时放行事件，保持父级滚动区域接手的能力。

只在算出的物理像素步长大于 1 时安装。100% / 200% 缩放和 macOS / Linux 行为完全不变，代价只有非整数缩放的 Windows 用户失去滚轮的逐帧缓动，换来跟手。滚动条拖动、键盘翻页仍走原链路。一次滚轮的位移保持 120 逻辑像素，与 QFW 原来的 `scrollValue(-angleDelta.y())` 一致，不改滚动距离。

考虑过保留动画、把动画步长放大到 4px：等于把滚动总量放大四倍，或要跟踪每帧并强制重绘，与 ADR 0019 放弃「间隔压到 1ms + 每跳重绘」的理由相同。若 Qt 后续支持非整数缩放下的亚像素平移，可直接删掉这个过滤器。判断它是否仍需要，把缩放调回 100% 即可：问题消失就说明还是同一条链路。
