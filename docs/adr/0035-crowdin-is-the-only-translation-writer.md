# 译文只在 Crowdin 写入，英文是回落语言

以前同一条译文有两个写入方：Crowdin，以及仓库里的 `.ts`（本地机翻脚本和直接改 `.ts` 的 PR 都写这里）。push 用仓库覆盖 Crowdin，pull 又用 Crowdin 覆盖仓库，8 份 `.ts` 每次都全量 diff、反复冲突，Crowdin 因此停用了三个月；支持的语言列表也在仓库里抄了 7 份以上。现在改为 Crowdin 是唯一写入方：仓库只上传原文、只下载译文，语言列表也以 Crowdin 项目的目标语言为准。另外，Android 沿用社区译文依赖 Crowdin 条款 §12.6（见 [Android ADR 0001](../../android/docs/adr/0001-closed-source-android.md)），绕过 Crowdin 提交的译文不在这条授权链上。

中文是原文。英文由项目保证完整：机翻补缺，标为未审校，再由人工审校。其他语言交给社区，缺译文的条目显示英文，不显示中文，因为看不懂中文的用户多半看得懂英文。浏览器扩展靠 `default_locale: en` 本来就是这样回落的。

## Considered Options

- **仓库为准，Crowdin 只做在线编辑入口**：两边改同一条译文就会互相覆盖，正是被替换掉的现状。
- **机翻覆盖全部语言**：Crowdin 上每加一种语言，它都会立刻被机翻到 100% 并进入正式包，"加语言"变成了"发布一种纯机翻语言"。
- **以 `Language` 枚举为语言列表的唯一来源**：Crowdin 后台仍要手动和枚举保持一致，新增语言还是要改两处。
- **安装第二个 QTranslator 做回落**：构建时把英文填进空条目，每种语言仍然只有一份 `.qm`，效果相同。

## Consequences

- 不再接受直接改译文的 PR，修订请到 Crowdin 提交。Discussions 里附带的译文文件，由维护者一次性导入 Crowdin。
- 新语言的桌面端完成度达到 60% 才加入仓库，三端一起加入，因为桌面端是主产品，Android 和扩展缺的部分显示英文。已经在仓库里的语言一直保留，不因完成度下降而移出，以免已选该语言的用户界面突然换成别的语言。
- 安装器的语言列表与应用相同，由 CI 生成。
